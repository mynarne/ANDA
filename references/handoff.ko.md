# 다음 작업자 인수인계

## 기준

ANDA = Agent + Notion + Discord Automation. Git 링크로 설치하는 스킬 패키지. 별도 웹/앱을 만들지 않는다. 한국어·영어 문서를 함께 유지한다.

## 먼저 실행

~~~sh
python3 -m unittest discover -s tests -v
python3 scripts/smoke.py
~~~

MANIFEST.json이 소스와 다르면 설치가 실패하는 것이 정상이다. 검토한 파일만 해시 목록에 포함하고 개인 상태를 절대 넣지 않는다.

## 실제 완료와 미완료

실제 로컬 설치·CLI·MCP subprocess·전체 스냅샷은 검증 대상이다. Notion/Discord 네트워크·자동 구성은 fixture 검증이며 실연결로 바꾸어 보고하지 않는다. 공식 Codex CLI의 작은 실제 요청도 이 클라우드의 읽기 전용 초기화 오류로 결과를 얻지 못했다. Claude/Gemini/Grok native 프로그램은 여기 설치되지 않았다.

두 프로세스의 기억 공유는 실제지만 두 AI 모델이 작업한 것과 다르다. SSH 원격 설정 생성은 실제지만 원격 연결 시험은 하지 않았다.

## 다음 인수 검증 순서

1. 허가된 쓰기 가능 호스트에 고정 커밋을 설치하고 별도 개인 상태 생성.
2. 사용자 본인의 노션 integration·봇 토큰을 비밀 저장소/보호된 런타임 환경에 주입. 기존 운영 자산이나 다른 세션에서 토큰을 추출하지 않음.
3. 신규 테스트 부모·guild를 명시하고 provision 계획 검토 후 적용. 실제 반환 ID와 권한 확인.
4. 새 테스트 요청 한 개 → 모델 응답 → 노션 페이지 ID·디스코드 메시지 ID를 각각 확인.
5. 다른 native AI 클라이언트에서 같은 MCP 기억을 읽고 출처를 확인. 일반 웹·앱 전체 대화는 자동 수집하지 않음.
6. 두 번째 기기는 동일 호스트의 SSH stdio에 연결. 별도 로컬 SQLite끼리 동기화된다고 설명하지 않음.
7. 중단·재시작·권한 철회·부분 실패 후 중복 전송 없는지 확인. 최소 48시간 관찰 후 상시 운영 선언.

## 남은 개발

- 노션 DB·뷰 템플릿과 DB 명령 수신.
- OAuth·OS별 supervisor 설치, 개인 원장 보관기간/삭제 정책, 대형 큐 제어.
- Gemini/Grok 실행 어댑터는 공식 기능과 도구 경계 검증 후 추가.
- provisioning의 unknown을 실제 리소스와 대조하여 복구하는 운영자 도구.

실제 외부 성공을 주장할 때는 대상 ID·반환 receipt·실행한 버전·검증 시각을 남긴다. 승인·로그인·실연결과 구현 코드는 별도 상태로 기록한다.
