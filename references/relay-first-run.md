# First run, repair and recovery

Start with `anda.py --home STATE relay-check`. It is an offline check and prints counts and booleans only, including existing source baselines and environment availability. Preserve existing approved values in protected config. Only ask for missing inputs or a specific scope that failed to verify. No read or write permission on a remote service is inferred from the local check. With approved credentials, `doctor --live` checks connector reads using GET. It does not test inserts or messages. Re-run after repairs. The first polling pass checks scope again and establishes per-scope baselines without processing existing content.

Use the format in [relay.example.json](relay.example.json) as a merge guide for a fresh state. A route has explicit project, semantic source and stage, private visibility, consent and selected destinations. Use a single owner-approved exact target per connector in this draft. Discord model execution requires all three configured legs, input archive to Notion and response delivery to both Notion and Discord. Other routes independently select their allowed destinations. An empty destination list permits local-only ingestion where a route supports it.

Guide the user through the official vendor UI only as needed. For Notion, create or reuse an internal integration, enable read and insert access and connect it only to the selected private page. For Discord, use the existing designated bot or walk the owner through the Developer Portal Bot page and official guild install for an approved bot. Enable Message Content Intent for visible text. In the exact private test channel, deny @everyone View Channel, grant no role an explicit view override, and grant the selected human members and bot access as individual entries. The bot needs View Channel, Send Messages and Read Message History. Set the approved Discord bot ID in intake.discord.bot_id, and match the exact selected destinations and allowlisted actors. Use hidden input in the user's own terminal or a protected secret store. Preserve verified IDs and ask for a replacement credential only if the existing credential is missing or rejected. Existing-endpoint onboarding can use `scripts/onboard.py --check --prompt-secrets` with the previously approved arguments on the owner's private terminal. No account access or external writes are assumed by a setup plan.

## Visible turns

Enable a hook provider in the project relay config with its absolute approved `cwd` and explicit session list. Register commands only in the selected project using the official local hook settings. For Codex, bind UserPromptSubmit and Stop to `anda.py --home STATE hook --project demo --provider codex --native`. Only documented `prompt` and `last_assistant_message` fields with a stable `turn_id` and session are ingested. Recursive Stop, subagents, hidden reasoning and transcripts are excluded. Claude Code uses those visible payload fields but its native input does not guarantee a stable turn identifier. The draft requires a stable event ID from an approved controller for this path, and skips native payloads without it. Native registrations have not been exercised live in this draft. [Codex hooks](https://developers.openai.com/codex/hooks/) · [Claude Code hooks](https://code.claude.com/docs/en/hooks)

A controlled project session can send explicit `anda.event.v1` JSON to `hook --provider controlled`. Supply `cwd`, `conversation_id`, stable `event_id`, and either `user_prompt` or `assistant_message` with visible `text`. Caller-supplied metadata is only trusted from approved local code. Never install global transcript readers. Do not copy signing material or session tokens between hosts.

## Pause and reconnect

Run `relay-pause pause` or stop the foreground worker before changing scope. A watched worker reloads the configuration before each cycle. Already in-flight requests may finish. Remove route consent or disable the intake/destination to revoke it and revoke credentials in the service when necessary. Reopening with changed source scope can establish a new source baseline. Pending deliveries keep the original target and are checked against current consent and scope before sending. Local outbox replay is idempotent at ingestion. Restore with `relay-pause resume` and start the worker explicitly.

Use `status` to inspect outcomes privately. Reconcile uncertain POSTs through positive receipt matching on the original authorized destination. Absence alone is not proof of non-delivery. Use explicit evidence before resolving an unknown attempt. Provider timeouts are not replayed automatically. Known transient delivery failures use bounded backoff. Offline capture can queue local turns on the authoritative host without connector access. Online sources are bounded, so a long outage or excessive backlog can create gaps. Stop and inspect privately before changing a cursor. No scheduler, resource or database was provisioned on Oracle.

## Notion author enrollment / 작성자 등록

Confirm in Notion that only the approved owner can edit the selected test page. The API can verify the exact non-public page, but cannot enumerate its sharing grants. An approved owner-only local enrollment process calls the bounded `anda.notion_author.enrollment` helper with a fresh synthetic challenge and a baseline of block IDs. The owner adds it as one new direct paragraph. The runner checks the authenticated block metadata for matching creator and last editor, a new block ID and exact page, rejects duplicate challenges and its own bot, then stores page, bot, author, proof block and the challenge digest in protected local config. This proves participation by the editor who received the challenge on the owner-controlled console. It does not independently resolve real-world identity. Never enroll a page whose owner-only edit access you cannot attest to. The proof text is not mirrored. No workspace user-information capability, PAT, name or email lookup is used.
